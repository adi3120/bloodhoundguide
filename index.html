03 / Find Domain Admins

Explore → Cypher → Saved Queries → search “Domain Admins”

Select All Domain Admins under Active Directory Domain Information. The current documented UI can auto-run selected queries; otherwise use its run/search control. For an explicit search scoped to the course domain, paste this in the Cypher editor:

MATCH p=(u:User)-[:MemberOf*1..]->(g:Group)
WHERE g.name = 'DOMAIN ADMINS@CORP.COM'
RETURN p

This follows direct and nested MemberOf relationships from users to the named group. Replace the group name if your lab uses another domain.

Verified in your import: JEFFADMIN@CORP.COM and ADMINISTRATOR@CORP.COM both have MemberOf edges to DOMAIN ADMINS@CORP.COM.

06 / Read the nodes and edges

Click a node to open its Entity panel. Expand Members, Member Of, Sessions, or Local Admin Privileges where available. Click a line to inspect the relationship.

RelationshipInterpretation
MemberOfA principal belongs to a group. Nested group membership can extend the chain.

07 / Collect fresh CE data with NetExec

Run NetExec on Kali against the domain controller. NetExec queries Active Directory and reachable Windows computers remotely, then creates the BloodHound ZIP on Kali. You do not need to copy a ZIP from the Windows machine.

Lab scope used here: domain corp.com, domain controller and DNS server 192.168.112.70, user stephanie. The password is requested interactively and is not stored in this guide.

Step 1 — understand the compatibility issue on this Kali machine

NetExec 1.5.1 is configured for BloodHound CE, but the globally available Python module is the Legacy collector. A Legacy schema ZIP may show as successfully ingested while failing to create CE local-group edges such as AdminTo. The following isolated setup downloads Kali’s CE collector under /tmp and leaves the global Python installation unchanged.

Step 2 — prepare the CE collector dependency

BH_WORK=/tmp/netexec-bhce-collector
mkdir -p "$BH_WORK"/{package,nxc,output}
cd "$BH_WORK"

apt download bloodhound-ce-python
BH_DEB=$(find "$BH_WORK" -maxdepth 1 -type f \
  -name 'bloodhound-ce-python_*.deb' -print -quit)
dpkg-deb -x "$BH_DEB" "$BH_WORK/package"

BH_MODULES="$BH_WORK/package/usr/lib/python3/dist-packages"
ln -sfn bloodhound_ce "$BH_MODULES/bloodhound"

cp "$HOME/.nxc/nxc.conf" "$BH_WORK/nxc/nxc.conf"
python3 - "$BH_WORK/nxc/nxc.conf" <<'PY'
import configparser
import sys

path = sys.argv[1]
config = configparser.ConfigParser()
config.read(path)
if not config.has_section("BloodHound-CE"):
    config.add_section("BloodHound-CE")
config.set("BloodHound-CE", "bhce_enabled", "True")
with open(path, "w", encoding="utf-8") as handle:
    config.write(handle)
PY

The symbolic link is intentional: Kali installs the CE module as bloodhound_ce, while this NetExec build imports it as bloodhound. Everything above remains inside /tmp/netexec-bhce-collector.

Step 3 — collect the domain data

BH_WORK=/tmp/netexec-bhce-collector
BH_MODULES="$BH_WORK/package/usr/lib/python3/dist-packages"

read -rsp 'CORP\stephanie password: ' BH_PASS
echo

cd "$BH_WORK/output"
NXC_PATH="$BH_WORK/nxc" \
PYTHONPATH="$BH_MODULES${PYTHONPATH:+:$PYTHONPATH}" \
netexec ldap 192.168.112.70 \
  -u stephanie \
  -d corp.com \
  -p "$BH_PASS" \
  --dns-server 192.168.112.70 \
  --bloodhound \
  -c All

unset BH_PASS

A successful run authenticates to DC1.CORP.COM, resolves the collection methods, queries the directory and hosts, and prints Compressing output into …_bloodhound.zip. The password is held only in the current shell variable and is cleared afterward.

What -c All collects in this NetExec build

The verified run resolved these methods: ACLs, object properties, local administrators, DCOM, RDP, PowerShell remoting, trusts, sessions, containers and groups. Session collection can complete with zero results; it records the state observable at collection time.

Step 4 — locate and verify the ZIP on Kali

BH_WORK=/tmp/netexec-bhce-collector
BH_ZIP=$(find "$BH_WORK/nxc/logs" "$BH_WORK/output" \
  -maxdepth 1 -type f -name '*_bloodhound.zip' \
  -printf '%T@ %p\n' 2>/dev/null | sort -nr | head -n1 | cut -d' ' -f2-)

printf 'ZIP: %s\n' "$BH_ZIP"
unzip -l "$BH_ZIP"
sha256sum "$BH_ZIP"

The tested run produced fresh-netexec-bloodhound-ce.zip. Its SHA-256 is c17f2e4f7a5e2a7bc7a539f2c593a0abdbf2c6fdc326e70b7e49b52240e0c4ad. The archive contains seven CE-schema JSON files covering computers, users, groups, containers, the domain, GPOs and OUs.

Step 5 — upload it to BloodHound CE

  1. Open Quick Upload in BloodHound.
  2. Click the upload area and select the path printed as BH_ZIP.
  3. Click Upload.
  4. Open View File Ingest History.
  5. Wait for the ingest to show Complete. Click its ID and confirm all seven files succeeded.
  6. Open Explore → Cypher and run the AdminTo and HasSession validation queries in section 08.

09 / When the lesson and your screen disagree

I uploaded the ZIP, but search finds nothing

Check upload completion and any parsing errors. Confirm the ZIP contains SharpHound data and that its format is supported by your CE build. An older course collector may require replacement with a CE-compatible SharpHound collector. Recollection should stay within your lab scope.

Objects exist, but no path is returned

Check the selected domain, endpoints, direction, and edge filters. Confirm the necessary memberships, local-admin relationships, and session data were collected. “No path” means none was found in the available graph with those filters.

The owned-principal query returns nothing

Confirm that you used Add to Owned, allow analysis to complete, and inspect the saved query’s tag and target conditions. Try the explicit Stephanie-to-Domain-Admins Pathfinding search to separate a tagging issue from missing relationships.

I cannot find the exact prebuilt query

Expand Saved Queries and clear restrictive platform/category/source filters. Search a shorter term such as “admin” or “owned”. Additional queries are available in the official query library; use its CE import workflow if needed.

The graph is too small to read

Increase browser zoom with Ctrl + Plus, collapse unused side panels, and use graph zoom/fit controls. Click a node for its full label. Browser zoom and graph zoom affect different parts of the display.
